# Security Policy

Riventa is an experimental hackathon prototype. Do not deposit real assets or upload real commercial documents.

Report vulnerabilities privately to the repository maintainers through a verified private channel. Do not publish exploitable details before a fix is available. Include affected component, reproduction steps, impact and suggested mitigation.

Security-critical areas: NEP-141 receiver validation, escrow conservation, asynchronous settlement callbacks, authorization, admin pause, document access grants, encryption-key handling, file parsing, AI prompt injection and indexer reconciliation.

No production security audit is implied. A production release requires independent contract audit, application/security review, privacy/key-management review, legal review and explicit release approval.
