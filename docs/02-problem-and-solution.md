# 2. Problem and Solution

## Problem hypothesis
Cross-border transactions coordinate parties, agreements, invoices, packing lists, certificates, inspections and payment obligations across organizations. Fragmented records can make it harder to spot inconsistent documents, establish evidence provenance and coordinate payment against agreed milestones. These are hypotheses; no market size, customer traction or measured impact is claimed.

## Solution
Riventa combines (1) customer-signed execution mandates, (2) agent-operated procurement and trade creation within mandate limits, (3) structured supplier acceptance, (4) private encrypted document exchange, (5) deterministic field extraction and cross-document checks with optional local-model explanations, (6) attributable inspector attestation and (7) NEAR-enforced conditional escrow settlement. The agent executes permitted operations; the contract enforces authority and money movement. This is a coordinated workflow, not a guarantee against fraud, default or physical performance.

## Why hybrid
The NEAR contract owns mandate authorization, trade state transitions, budget reservations and escrow liabilities. Private file bytes and detailed reports stay off-chain. Backend services handle deterministic policy checks, encryption, parsing, analysis, agent orchestration and indexing. The agent signs with its own account; it never uses a customer's private key. Frontend presentation is not a security boundary.

## Trust assumptions
Users rely on wallet keys for account control, contract code for encoded rules, the token contract for token behavior, storage controls for confidentiality/availability, inspectors for physical observations and human reviewers for documentary decisions. Each trust dependency is disclosed.
